# EduMaster · 화학 문제 스튜디오

**내 샘플 파일 → 로컬 Gemma 4 12B → 변형 문제·정답·해설** 흐름입니다. API 키 없이 현재 PC의 모델로 생성합니다. 수정본의 사진·PDF는 로컬 Qwen3-VL 4B로 읽고, TXT·DOCX는 본문을 추출합니다. 독립 화학 검산·교사 승인까지 완료한 상태는 아닙니다.

## 바로 실행

웹의 **생성 모델**에서 Gemma / Gemini / 둘 다 비교를 선택할 수 있다. Gemini 기본값은 실제 생성한 2.5 Flash이며 3.8 Flash도 선택할 수 있다. 3.8은 검사 당시 Google의 높은 수요로 긴 문제 생성에 503을 반환했다. 선택한 모델은 자동으로 바꾸지 않는다. 같은 본문·입력 모드·원본 이미지로 두 모델을 동시에 호출하고 먼저 완료한 결과부터 표시하며, 하나가 실패해도 다른 결과를 보존한다. Gemini는 Google API로 본문·원본 이미지를 보내며 할당량과 API 요금이 적용된다. 키는 무시되는 서버 런타임의 비공개 파일에 저장하고 HTML·JS·응답에 포함하지 않는다. 키 파일의 읽기 권한은 서버 사용자·작업 계정으로 제한한다. 이번 비교 기능은 웹에 추가한 것이며 Windows UI에 추가한 것은 아니다.

현재 외부 웹은 사용자 요청으로 임시 공개 테스트 모드다. `artifacts/web/public-test.txt`의 UTC 만료 시각까지 접속 코드 없이 업로드·생성을 허용하며, 만료 시 인증을 다시 적용한다. 시작 시 2시간보다 긴 공개 설정은 거부하며 익명 업로드·생성은 각각 20회까지다. 파일 크기·단일 작업·원본 검산 제한은 유지한다. 접속 화면에 ‘공개 테스트’가 표시된다. 인증 안내는 공개 모드가 끝났을 때 적용된다.

외부 웹의 일반 주소에는 인증 정보가 없습니다. 첫 접속에는 접속 코드 입력 화면이 표시되며 인증 전 이미지 업로드·생성을 차단합니다. 기존 인증 링크 또는 접속 코드로 연결합니다. 접속 유지는 사용자가 체크했을 때만 해당 브라우저에 저장하며, ‘접속 해제’로 지울 수 있습니다. 코드와 인증 링크는 공개 문서에 넣지 않습니다. 저해상도 원본 반응량 자료는 원본 질문·표를 직접 확인한 뒤 ‘몰질량·상댓값으로 본문 수정’을 눌러 오독을 수정할 수 있습니다. 이 버튼은 자동 인식 개선이 아닙니다.

**[프로그램 실행.cmd](프로그램%20실행.cmd)**를 더블클릭합니다. 설치판은 `artifacts/installer/EduMaster-MVP-Setup.exe`이며 실행판에는 .NET 런타임이 포함돼 있습니다.

1. 생성용 Gemma 이미지 서버(`127.0.0.1:8092`)와 인식·대조용 Qwen 서버(`127.0.0.1:8091`)를 사용합니다. 폴더의 실행 도구는 두 서버를 자동 실행합니다. 기존 Blog용 텍스트 서버 `8089`는 그대로 유지합니다. **AI 설정**에서는 로컬 서버 주소와 연결 상태만 확인합니다. 키 입력은 없습니다.
2. **샘플 파일 선택** 또는 드래그 앤 드롭으로 **PDF·PNG·JPG·TXT·DOCX** 파일 하나를 넣습니다. 최대 10MB, PDF는 5페이지까지, 본문은 12,000자까지 읽습니다. 생성할 문제 한 개만 본문에 남기고 수식·조건을 확인합니다.
   **넣은 자료**에서 ‘문제 → 변형 문제’ 또는 ‘풀이·해설 → 새 문제’를 선택합니다. 풀이만 있어도 핵심 개념·계산·관계를 확인할 수 있으면 이를 바탕으로 질문과 보기를 구성합니다.
3. **변형 문제 생성**을 누르면 자료로 만든 새 문제·보기 5개·정답·해설·풀이 단계가 나타납니다. 정답·해설을 미리 입력할 필요는 없습니다.
4. **AI가 읽은 기준 문제 확인**에서 원문과 비교하고, 바뀐 조건을 확인합니다. 복사·PDF 미리보기·저장도 가능합니다.

PDF·사진은 원본 이미지와 확인·수정한 본문을 함께 Gemma에 전달해 생성합니다. 아래첨자·분수·표·분자 그림은 인식이 부정확하거나 빠질 수 있으므로 원본과 인식 본문을 확인해 주세요. 여러 문제의 일괄 생성은 후속 작업입니다.

HWP와 수식·그림이 있는 DOCX는 **PDF로 저장**한 뒤 넣어 주세요. 일반 DOCX는 텍스트만 읽으며 수식·그림이 감지되면 불완전한 본문으로 진행하지 않습니다. 이미지가 흐리거나 문제 조건이 빠졌거나 화학 문제가 없는 자료는 실패 사유를 안내합니다. PDF 미리보기에는 WebView2가 필요하며 설치판은 누락 시 Microsoft 부트스트래퍼로 준비합니다.

Windows 프로그램의 현재 기본 생성은 로컬 Gemma이며 Gemini 키 설정을 읽지 않습니다. 웹은 생성 모델에서 Gemini 또는 둘 다 비교를 선택하면 Google API를 호출하고 API 할당량·요금이 적용됩니다. 다른 모델로 자동 대체하지 않습니다. 서버가 꺼져 있으면 연결 오류를 표시합니다. 별도의 시연 버튼만 준비된 예시 2개를 사용합니다. 모델 파일과 서버는 설치판에 포함하지 않습니다. 현재 PC에 이미지 모델은 설치했습니다. 다른 개발 PC에서는 `scripts/install-vision.py`로 공식 Qwen3-VL 4B 가중치 약 2.95GB와 Gemma 12B 이미지 projector 약 175MB를 준비합니다. Gemma 본체는 기존 모델 파일을 사용하며 `scripts/start-vision.ps1`, `scripts/start-gemma-vision.ps1`로 실행합니다.

입력·결과는 `%LocalAppData%/EduMaster/workspace.json`, 파일 사본은 `imports/`, 로컬 주소는 `local-ai.json`에 저장합니다. 기존 입력과 키 설정 파일은 보존합니다. 입력 변경 시 이전 결과가 해제되며 실패·취소 시 입력은 유지됩니다. 생성 중 단계·경과 시간·취소 버튼을 표시하고, 실패 사유와 재시도 버튼을 결과 영역에 보여 줍니다.

## 개발·확인

### 입력·생성 장애 수정 (0.6.0)

실제 PDF 원본에서 300초 생성 시간 초과를 재현했습니다. 원문을 AI가 통째로 재출력하는 경로를 줄이고 입력 지문은 앱이 지문 식별값으로 결과에 연결합니다. 답변 토큰은 1,800개로 제한하며 잘린 답변은 실패로 처리합니다. 이미지 선택 시 원본 미리보기와 경과 시간·취소를 바로 표시하고, 읽기는 120초로 제한합니다. 읽기와 생성은 서버에서 한 작업씩 처리합니다. 보관 만료·서버 재시작 후에는 복구된 본문만으로 생성하지 않고 원본 재선택을 안내합니다.

원본 OCR이 ‘몰질량’을 ‘물질량’으로 읽으면 기존 검산이 실행되지 않아 잘못 바뀐 표가 성공 처리되는 결함도 재현했습니다. 현재 이 반응량 질문은 원본 용어를 확인·수정하기 전 생성을 차단합니다. 자동으로 용어를 바꾸지 않습니다. 검산 가능한 좁은 반응량 유형은 코드가 모든 질량을 같은 2배로 바꾸고 상대 몰비를 유지한 본문을 구성하며, Gemma는 원본 이미지와 이 본문을 받아 보기·해설을 작성합니다. 새 표와 정답은 독립 계산으로 다시 확인합니다. 필기로 적힌 x의 정답을 새 문제 조건으로 공개하지 않습니다. 다른 유형은 계속 AI 초안이며 독립 계산 보장은 없습니다.

자동 테스트 79개를 통과했습니다. 저해상도 PDF 원본의 OCR 품질 자체가 해결된 것은 아니며, 원본과 본문·표·단위를 확인해야 합니다. 원본 오독을 자동 보정해 성공한 것처럼 처리하지 않습니다.

실제 호출에서 원본 오독은 1초 안에 차단했고, 원문을 확인해 본문 용어를 수정한 뒤 같은 원본 이미지로 약 156초 만에 변형·독립 검산·정답 2/5를 확인했습니다. 풀이 텍스트 입력은 약 61초 만에 20 g 질문·정답 0.2 mol을 생성했습니다. Windows 설치판은 0.6.0으로 업데이트했으며 기존 입력 해시와 웹/Core 일치를 확인했습니다. Windows 실제 화면에서 생성·PDF 출력까지 검증한 것은 아닙니다.

### 밖에서 웹으로 확인

현재 서버의 `/edumaster/` 경로에 모바일 웹 MVP를 배포했습니다. 전달된 접속 링크로 열고 **텍스트 예시 넣기 → 변형 문제 생성**, 또는 내 파일 업로드로 확인합니다. 웹 화면은 Linux 서버의 `edumaster-web` 사용자 서비스에서 제공하며, 생성·파일 읽기는 SSH 터널을 통해 Windows의 같은 C# 코드와 Gemma 4 12B를 사용합니다. 해당 PC가 꺼지거나 절전 상태가 되면 생성·파일 인식은 중단됩니다.

웹에서는 업로드 후 인식 본문을 확인·수정할 수 있고 진행 단계·경과 시간·취소·보기·정답·해설·복사·브라우저 인쇄/PDF 저장을 제공합니다. 업로드 파일은 인식 후 디스크에서 삭제합니다. 렌더링 원본은 생성·대조에 쓰도록 서버 메모리에 약 2시간 보관하며, 만료·서버 재시작 후에는 파일을 다시 선택해야 합니다. 입력·결과는 브라우저 탭에 보관합니다. 큰 이미지의 결과는 브라우저 저장 한도를 넘으면 새로고침 후 복구되지 않으므로 인쇄/PDF로 보관합니다. 별도 접속 토큰은 링크의 fragment로 전달하고 API 요청 헤더에서만 사용합니다. Windows 앱의 기존 입력은 웹에 복사하지 않습니다.

Windows 연결 재실행은 `웹 프로그램 실행.cmd`, 사용자 서버 배포는 `scripts/deploy-web-route.py`, 외부 실제 파일→생성 검사는 PowerShell 7의 `scripts/test-web.ps1`입니다. 서버 배포 스크립트는 SSH 키와 사용자 권한만 사용하며 암호나 sudo를 사용하지 않습니다. 별도 재조판 이미지로 외부 웹의 실제 업로드→생성·정답 검사 **17/17**를 통과했습니다. PDF 원본 문제의 인식·생성 품질을 검증한 결과는 아닙니다.

```powershell
dotnet run --project src/EduMaster.App
dotnet test tests/EduMaster.Core.Tests -c Release
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

2026-09-17 수정본은 자동 테스트 **67/67**, 별도 재조판 이미지의 외부 이미지→변형 생성 검사 **17/17**를 통과했습니다. Windows OCR의 글자 수 검사만으로 인식 성공을 판정했던 기존 검증은 충분하지 않았습니다. 현재는 반응식·표·분모·몰질량 표기를 검사합니다. 반응량 표의 좁은 유형 `A + bB → 2C + 2D`는 소비 질량비와 상대 몰분율로 b·x·정답을 계산하여 새 표와 보기·해설을 검산합니다. 다른 화학 유형의 독립 검산·교사 승인·RAG·전체 기준셋 평가는 후속 작업입니다.

**PDF 반응량 문제 읽기 / PDF 분자 구조 문제 읽기**는 PDF에서 추출한 원본 `01_반응량_문제.png`와 `04_분자구조_문제.png`를 사용합니다. 표 배치·수식·분류도 화살표·정답 표시·필기를 그대로 보존합니다. 원본 이미지의 해상도는 각각 321×385, 536×675이며 확대해도 원래 없던 세부 정보가 생기지는 않습니다. 원본의 ‘몰질량/물질량’ 오독은 아직 남으므로 인식 본문을 원본과 확인해야 합니다.

이전 기본 예시 `07_반응량_고해상도예시.png`는 표·글자 배치를 다시 만들고 수식을 `M_A~M_D`로 바꾼 재조판 자료입니다. `08_직선그래프_연결관계예시.png`는 PDF에 없는 별도 제작 자료입니다. 두 자료는 웹의 **별도 제작 테스트 자료 · PDF 원본 아님** 영역으로 분리했습니다. 제작 예시의 성공을 PDF 원본 처리 성공으로 간주하지 않습니다. `scripts/sync-pdf-samples.py`는 PDF 내장 이미지 바이트·원본 잘라낸 픽셀과 기본 샘플을 대조하며, 재조판 생성 스크립트는 원본 기본 샘플을 덮어쓰지 않습니다.

빌드에는 .NET SDK 10.0.301과 최초 NuGet 복원이 필요합니다. build.ps1은 테스트·Windows 실행판을 만들고, `tools/cache/inno/ISCC.exe`와 WebView2 부트스트래퍼가 있으면 설치판도 만듭니다. 현재 PC 설치만 확인했고 다른 PC·코드 서명·상용 배포 준비는 후속 작업입니다.

## 원본 이미지와 연결 관계 (0.5.0)

사진·PDF 생성은 **원본 렌더링 이미지 + 사용자가 확인한 본문**을 함께 사용합니다. Qwen3-VL이 축·곡선·교점 또는 원자·결합을 노드/연결/조건으로 구조화하고, Gemma 4 12B 이미지 서버가 원본 이미지와 본문·시각 정보를 함께 받아 문항을 작성합니다. 생성된 문항·정답·해설을 Qwen3-VL에 원본 이미지와 함께 다시 보내 모순을 확인합니다. 판독 불확실·불완전한 연결·대조 실패·원본 만료 시 결과를 내지 않고 구체적인 오류를 표시합니다. AI 대조를 독립적인 정답 보장으로 간주하지 않습니다.

첫 MVP는 **그림의 연결·축·좌표·결합·그림 내부 숫자는 유지하고, 그림 밖 조건·질문을 변형**합니다. 그림이 필요한 문항은 원본 시각 자료를 결과와 인쇄/PDF에 함께 첨부합니다. 원본 이미지에 함께 찍힌 기존 본문은 기준 자료이며 새 조건은 변형 본문을 따릅니다. 곡선·분자 구조 자체를 바꾸거나 새로운 그림을 다시 그리는 기능은 아직 없습니다. 표 문제는 새 표를 본문에 출력하며 이전 표 이미지를 새 표로 제시하지 않습니다.

실제 외부 브라우저에서 그래프 예시 읽기 → 생성 → 원본 대조 → 그림 표시를 확인했습니다. 원점–A(2,4)–B(4,8) 연결은 유지하고 질문 x=3을 x=5로 변형하여 정답 10을 출력했습니다. 결과 PNG 1700×1545가 정상 로드되는 것도 확인했습니다. 이 검증은 단순 직선 그래프 예시이며 복잡한 곡선·분자 구조 전체의 정확도를 보장하지 않습니다. 증거는 `artifacts/evidence/web/graph-smoke.json`, 표 검사는 `web-smoke.json`입니다.

Windows 앱은 저장된 원본 첨부에서 생성할 때 다시 이미지를 렌더링하고 웹은 임시 원본 식별자를 사용합니다. 기존에 읽은 첨부도 이미지 전달 없이 생성하지 않습니다. 그래프 예시는 [08 연결 관계 PNG](docs/참고자료/샘플자료/08_직선그래프_연결관계예시.png)이며 PDF에서 추출한 자료가 아닌 검증용 제작 자료입니다.

### Gemma 직접 이미지 입력

`127.0.0.1:8092/props`에서 `vision:true`를 확인한 후 PNG/JPG 원본을 `image_url`로 생성 요청에 첨부합니다. 이미지 지원이 꺼진 서버에서는 텍스트로 자동 전환하지 않고 오류를 표시합니다. Windows의 기존 기본 주소 8089 설정은 파일을 덮어쓰지 않고 로딩 시 8092로 연결합니다.

[llama.cpp 공식 Gemma 12B projector](https://huggingface.co/ggml-org/gemma-4-12B-it-GGUF/tree/main)의 BF16 파일(175,115,616 bytes)을 설치했습니다. OCR 본문을 전혀 주지 않은 그래프 이미지 시험에서 Gemma가 A=[2,4], B=[4,8], slope=2를 읽었습니다. 증거는 `artifacts/evidence/web/gemma-direct-image-probe.json`입니다.

RTX 5080 16GB에서 기존 공유 Gemma와 공존하도록 전용 Gemma는 GPU 12레이어, Qwen은 4레이어를 사용하며 나머지는 CPU에서 처리합니다. 테스트 시 Gemma 출력은 약 9 tokens/s이므로 기존 텍스트 전용 생성보다 느립니다. GPU 여유와 인식 품질을 무시한 전 GPU 중복 로드는 피합니다. 새로운 그림을 그리는 기능과 복잡한 도형·분자의 전체 품질 보장은 아직 없습니다.
