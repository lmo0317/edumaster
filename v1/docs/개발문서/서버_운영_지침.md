# EduMaster 서버 운영 및 배포 지침

EduMaster의 공개 웹과 문제 생성 API는 112 Linux 서버에서 실행됩니다. 화면 변경은 실제 공개 주소에서 확인합니다.

## 구성

- 앱 경로: `/home/lmo0317/apps/edumaster`
- 공개 주소: `https://minohlee.mooo.com/edumaster/`
- 주요 화면: `/create/` 문제 생성, `/learning/` 피드백, `/system/` 시스템 설명
- 정적 파일: `public/`; API: `backend/`의 `edumaster-api` 서비스
- 보관 경로: `backend/reports/`, `backend/job-cache/`, `backend/learning-archive/`

## PDF 저장

문제 생성 화면의 **PDF 저장**은 서버에서 보고서를 만든 다음 기기로 내려받습니다. 저장된 PDF의 목록·다시 보기 화면과 목록 API는 제공하지 않습니다. 이전에 저장된 PDF 파일은 서버에 보존합니다. `/result/`은 메인으로 이동합니다.

문제 생성 화면의 **학습 데이터 추가**는 **PDF 저장**과 같은 전체 보고서 렌더러로 원본 문제·해설 이미지와 모든 STEP의 문제·상세 해설·수식을 PDF로 먼저 만듭니다. 파일이 완성된 뒤 학습 세트의 `pdfReportId`에 연결합니다. PDF 생성이 실패하면 학습 저장을 진행하지 않습니다. 이미 같은 내용의 PDF를 만들었다면 그 파일을 재사용하며, 해설·STEP·보기·그림이 바뀌면 새 파일을 만듭니다.

피드백 화면 `/learning/`의 **세트 PDF 다운로드**는 연결된 PDF 파일을 그대로 내려받습니다. 다운로드 시 보고서를 재구성하거나 PDF 생성기·LLM을 호출하지 않습니다. 연결 정보와 파일은 서버 재시작 후에도 유지됩니다. PDF가 연결되지 않은 과거 세트는 다운로드 버튼을 비활성화하고 생성 결과 화면에서 PDF와 함께 다시 저장하도록 안내합니다. 기존 문제별 피드백은 유지합니다.

- `POST /api/reports`: 생성 화면의 전체 보고서를 PDF로 생성
- `POST /api/learning/jobs/{id}`: `sourceId`, 완성된 파일의 `pdfReportId`와 함께 학습 데이터 저장
- `GET /api/learning/jobs/{id}/status`: 학습 저장 여부와 PDF 존재 여부
- `GET /api/learning/jobs/{id}/pdf`: 학습 세트에 연결된 기존 PDF 다운로드
- `GET /api/reports/{id}/file?download=true`: 생성 직후 해당 PDF를 다운로드
- `GET /api/reports` 및 매개변수 없는 PDF 열기: 제공하지 않음

## 배포와 확인

1. 변경 파일을 빌드·테스트하고 서버의 현재 파일을 백업합니다.
2. 정적 파일은 `public/`과 `backend/wwwroot/`에 함께 반영합니다. API 변경 시 게시된 `EduMaster.Web.dll` 및 필요한 `EduMaster.Core.dll`을 `backend/`에 반영하고 `edumaster-api`를 재시작합니다.
3. 공개 주소의 메인·문제 생성·피드백·시스템 화면과 인증된 API를 확인합니다. PDF 저장을 수정했다면 새 보고서의 다운로드 응답을 확인합니다.
4. 기존 `reports/`, `job-cache/`, `learning-archive/`의 사용자 데이터는 배포 과정에서 삭제하지 않습니다.

## 교사 피드백 적용

원본 해설은 정답만 확인하는 자료가 아니라 생성 풀이의 기준입니다. 이미지에서 읽은 보조 문자·치환·가정·실험 비교·모순 판정과 STEP 순서를 유지합니다. 판독과 검산이 충돌하면 원본을 다시 읽으며 코드 풀이로 몰래 교체하지 않습니다. 긴 풀이 이미지는 원본을 보고서에 보존하고, 판독할 때만 겹치는 확대 구간으로 나눠 제공합니다.

중간 문제에도 원본의 자세한 해당 STEP 해설을 전달합니다. 저장 결과의 `sourceExplanation/sourceSteps`는 전체 원본이고 `learningSteps`는 해당 연습 문제의 허용 범위입니다. 통합 변형은 실제 앞 문제의 조건·질문·풀이 데이터를 참조해 구성하며, 교사 풀이가 있는 결과를 반응량 코드 템플릿으로 덮어쓰지 않습니다. 수치 변형 선택은 계속 지원합니다.

지원 반응량 표의 통합 변형에서는 실험별 잔류 A/B 배치를 바꿔 몰수·상댓값 사이의 자료 관계를 다시 설계합니다. 숫자를 서로 다른 배수로 바꾸거나 설명을 덧붙이거나 x의 위치만 옮긴 결과를 통합으로 인정하지 않습니다. 원본의 두 실험 비교가 필요한 첫 STEP과 보조 문자 도입 위치·몰분율 계산 위치도 별도로 검사합니다.

수치·조건이 맞고 해설 순서만 틀리면 본문·보기·정답을 유지한 채 해설을 보완합니다. 검토 응답이 잘리거나 형식이 깨지면 검사 응답만 한 번 복구하며, 여전히 확인할 수 없으면 미확인 상태를 유지합니다. `/api/jobs/{id}/retry-check`에서도 보관된 최종 초안의 풀이 순서를 보완할 수 있습니다. 새 코드 검사에서 이전 완료 세트가 탈락하면 완료 표시를 취소하고 같은 입력의 통과한 앞 단계만 재사용합니다.

교사 피드백은 `/learning/`의 전체 명령어에서 해야 할 것과 하지 말아야 할 것으로 관리합니다. `PUT /api/learning/guidance`로 저장된 공통 지침과 교사 승인된 문제별 피드백 검색 결과가 다음 생성에 함께 전달됩니다. 이는 프롬프트·RAG 반영이며 모델 가중치 학습은 아닙니다. 지침 변경은 생성 캐시 식별값에 포함됩니다. 이미 생성된 보고서는 자동으로 다시 만들지 않습니다.

## 기본 프롬프트 조회

`/learning/?tab=guidance`의 전체 생성 명령어 탭에서 기본 생성 프롬프트와 해야 할 것·하지 말아야 할 것을 함께 확인합니다. `GET /api/learning/prompts`는 DeepSeek/Gemma 생성기가 실제로 쓰는 `BuildSystemPrompt`에서 읽어 오며, 통합 변형·수치 변형·STEP 연습에 따른 내용을 각각 제공합니다. 기본 프롬프트는 읽기 전용이며, 두 추가 명령어는 기존 저장 기능으로 수정합니다. 입력 식별값과 실제 STEP 수는 미리보기에서 변수로 표시하고 실제 생성 때 입력에 맞춰 채웁니다. 조회용 모델 선택은 생성 모델 설정을 바꾸지 않습니다. 기본 프롬프트 조회 실패 시에도 추가 명령어 편집과 저장은 유지합니다.

## 공통 화면 디자인

메인·문제 생성·피드백·학습 내용·시스템 설명은 `wwwroot/ui.css`의 공통 화면 스타일과 동일한 상단 메뉴(메인 / 문제 생성 / 피드백 / 시스템 설명)를 사용합니다. 현재 기능을 메뉴에 표시하며 학습 내용은 피드백 아래의 페이지입니다. 로고·메뉴 간격·화면 폭·글꼴·제목·기본 버튼·카드·하단 표시가 공통 적용됩니다. 문제 생성의 접속 상태와 로그아웃은 상단 메뉴에서 분리해 제목 아래에 둡니다. 모바일에서도 주요 메뉴는 숨기지 않습니다.

공통 스타일은 화면용이며 PDF 보고서의 `style.css`와 출력 구조는 별도로 유지합니다. 정적 파일 변경은 `public/`과 `backend/wwwroot/`에 함께 반영하고, `scripts/ui-unification-e2e.py`로 여섯 화면(피드백 두 탭 포함)을 PC·모바일·작은 휴대폰·태블릿 폭에서 확인할 수 있습니다. 이 검증은 데이터를 수정하거나 모델을 호출하지 않습니다.

새 정적 파일은 웹 게이트웨이의 `assets` 허용 목록에도 등록합니다. `ui.css`가 목록에 없으면 공개 주소에서 404가 발생합니다. 목록 변경 시 `edumaster-web`만 재시작하며 API와 진행 작업은 유지합니다.
