# 화학 AI 학습프로그램 2개월 개발 일정

갱신일: 2026-09-17 · 기간: **2026-10-01~2026-11-30** · 상태: 01 화면·파일 입력 및 02 로컬 Gemma 연결을 09/17 선행 구현, 실제 AI 품질 검증은 미착수

사용자 요청으로 Windows 샘플 UI를 먼저 만들었습니다. 10월 1일 정식 개발 시작과 2개월 목표는 유지하고, 01 기간에는 선행 결과를 확인·보완한 뒤 02로 진행합니다.

**10월 2일 첫 화면 시연 → 11월 6일 수동 채점 MVP → 11월 30일 맞춤 숙제·간단 OMR을 포함한 MVP 완료**를 목표로 합니다. 기존 장기 일정을 이 계획으로 대체합니다.

## 2개월에 완성할 범위

개발자 1명이 주 업무로 진행하고, 화학 담당자가 기준 문제 준비와 검수를 함께 한다고 가정합니다. 화학 유형 하나·AI 공급자 하나·요청당 후보 하나·예시 반 하나로 범위를 고정합니다.

문제 입력, 실제 AI 생성, 독립 검산, 교사 승인, 승인 문제은행, 5문제 PDF, 가상 학생 2명의 수동 채점, 간단한 맞춤 숙제, OMR 한 장의 판독·사람 검수까지 연결합니다. 마지막 주에는 한 기관의 실사용 준비를 점검합니다.

기능별 작업과 테스트는 [단계별 개발 문서](../개발문서/README.md)를 따릅니다. 이번 일정은 각 단계의 최소 범위와 다음 단계에 필요한 필수 보완을 대상으로 합니다.

실행 형태는 [Windows 기술 비교·추천](../개발문서/윈도우_기술스택.md)의 C#·.NET 10 + WPF 설치형 앱을 우선안으로 합니다. 첫 시연에서 표시·PDF·설치를 확인해 구성을 고정합니다. [AI 시스템 설계](../개발문서/AI_시스템_설계.md)에 따라 로컬 Gemma로 먼저 완성하고, DeepSeek 기본 전환·벡터 검색은 후속 평가 대상으로 둡니다.

## 초반 2주에는 이렇게 진행

- **10/01:** C#·.NET 10·WPF 실행 환경과 내부 서비스·입력 화면을 연결하고 예시 문제 한 개를 넣습니다.
- **10/02:** 저장·샘플·복구·오류·첫 설치판과 WebView2 표시/PDF를 작게 확인해 구성을 고정합니다.
- **10/05~10/08:** 첫 유형과 계산 스키마를 정하고 로컬 Gemma 호출·3개 참고 자료·계획/작성 프롬프트·C# 독립 계산기를 연결해 시연합니다.
- **10/12~10/16:** 오류 후보 차단과 교사 검토를 끝내고 기준셋 분리·하네스 평가·치명 오류 수정을 마칩니다. 계산·AI 기능이 설치판에서도 작동하는지 확인합니다.

화학 담당자는 10월 1일부터 기준 문제 준비를 함께 진행합니다. 10월 5일에는 승인 기준 문제 3개, 10월 16일에는 사용 가능한 기준셋 20~30개와 평가 결과가 필요합니다. **02의 기준셋 평가 조건은 일정을 줄여도 유지**합니다.

## 이번 일정에서 뒤로 미룰 것

- 복수 후보·고급 검색·고급 편집기·대량 등록과 다기관·SSO: 기본 문제 관리가 완성된 뒤 별도 확장합니다.
- 여러 화학 유형·분자 구조·가정 모순·반전 생성: 첫 유형의 품질을 확인한 뒤 [선택 확장](../개발문서/09_선택_확장.md)에서 진행합니다.
- 정교한 선지 진단·숙련도·장기 복습: 이번에는 최근 오답 항목을 사용하는 간단 추천으로 시작합니다.
- 휴대폰 왜곡 사진·다중 페이지·자동 확정: 이번 OMR은 양호한 한 장 스캔과 사람 전체 확인으로 한정합니다.
- **한 반 4주 실사용 파일럿:** 실사용 준비 점검을 통과한 뒤 별도 일정으로 진행합니다. 11월 30일까지의 완료 범위에는 포함하지 않습니다.

## 매주 끝내는 방식

정상 흐름을 먼저 연결해 시연하고, 해당 단계의 간단 테스트와 앞 단계 대표 흐름을 확인합니다. 실제 결과와 남은 문제는 단계별 MD에 기록하고 이 표에는 상태와 목표 기간만 갱신합니다.

01~07은 로컬·예시 데이터로 개발합니다. 외부 접속이나 실제 학생 데이터를 먼저 도입한다면 08의 해당 보호를 앞당겨 적용합니다. 계정·파일·비용의 기본 제어는 관련 기능을 만들 때부터 준비해 마지막 주에는 통합 확인합니다.

검증 실패와 치명적인 정답·채점 오류를 완료 처리하지 않습니다. 선택 보완은 미룰 수 있지만 독립 검산·교사 승인·버전 보존·정확한 채점·실사용 보호는 생략하지 않습니다. 필수 조건이 실패하면 원인과 수정 계획을 기록하고 목표 일정도 실제 상황에 맞춰 갱신합니다.

- [ ] 실제 AI 호출·독립 계산·교사 승인이 연결되고 샘플 결과와 구분됩니다.
- [ ] 승인 문제와 확정 학습지·정답표가 보존되고 두 학생의 채점·추천이 섞이지 않습니다.
- [ ] PDF와 OMR 한 장의 출력·판독·사람 확인을 실제 자료로 확인했습니다.
- [ ] 이번 지원 범위의 권한·예산·백업 복구와 필수 실패 사례가 확인되었습니다.
- [ ] 미완료 보완·제한 사항·후속 파일럿을 명시하고 실행·테스트 기록을 인계했습니다.
