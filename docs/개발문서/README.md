## 완료 기준과 기록

현재 단계의 최소 범위부터 끝내고 해당 파일의 간단 테스트와 앞 단계 대표 흐름을 확인합니다. 다음 단계 조건에 명시한 보완은 수행해야 합니다. 예를 들어 02의 기준셋 평가를 끝낸 뒤 03으로 확대합니다. 08의 준비 점검과 4주 파일럿도 따로 기록합니다.

현재 단계 파일 끝에 아래 내용을 기록하고 위 표의 상태를 바꿉니다.

```md
### 완료 기록 실제 날짜
- 완료 범위: 최소 범위 / 실제 끝낸 보완
- 실행 방법: 개발 명령 / Windows 설치 파일과 실행 방법
- 확인 화면: 캡처 경로 또는 화면 결과
- 테스트: 케이스별 결과, 자동 / 수동 구분
- 데이터와 AI: 예시 / 실제 호출, 저장 위치
- 남은 문제와 다음 작업:
- 다음 단계 조건: 통과 / 미통과, 이유
```

샘플 시연·실제 AI 호출·내부 MVP·실사용 완료를 구분합니다. 생성 문제는 독립 검증·교사 확인 전에 배포하지 않습니다. 승인 문제와 확정 학습지는 버전을 보존하고 답안은 실제 받은 문제 순서·정답표에 연결합니다. 수정·재처리는 중복 누적하지 않습니다.

01~07은 로컬 예시 데이터로 확인합니다. 현재 AI는 기존 로컬 Gemma 서버를 사용하고 API 키를 요구하지 않습니다. 입력·저장·AI 오류와 긴 작업의 진행 상태를 화면에 표시합니다. 외부 API를 추가할 때에는 키를 보호하고 WebView2·번들·로그에 넣지 않습니다.
