# 01 화면·파일 입력 MVP

상태: 파일 입력·화면 최소 범위 완료 · 2026-09-17 · 다음: [02 실제 AI 생성과 검증](02_실제_AI_생성.md)

## 이번 단계에서 끝낼 것

내 샘플 파일을 넣고 기준 자료를 확인한 뒤, 변형 결과를 보는 Windows 화면과 저장 흐름을 만듭니다.

```text
파일 선택/끌어 놓기 → 기준 자료 확인 → 변형 생성 → 문제·정답·해설 → 저장·다시 열기
```

화면과 파일 입력은 완료했습니다. 로컬 Gemma 호출과 로컬 이미지 인식은 02를 앞당겨 연결하고 실제 동작을 확인했습니다. 화학 기준셋 품질 평가는 아직 없습니다. 독립 검산·교사 승인까지는 02의 완료 조건입니다.

## 최소 구현

- [x] **S01-01 실행 화면** — C#·.NET 10·WPF 창, 런타임 포함 실행판, 설치판, WebView2 PDF 미리보기. [실행 안내](../../README.md)
- [x] **S01-02 문제 입력** — PDF·PNG·JPG·TXT·DOCX 파일 선택·드래그 앤 드롭. TXT·일반 DOCX 본문 표시·수정, 이미지 미리보기, 원본 열기. 정답·해설은 선택 사항. 수식·그림이 있는 DOCX는 PDF 변환을 안내합니다.
- [x] **S01-03 저장과 복구** — 기준 입력·파일 사본·결과를 고유 ID와 내용 해시로 연결해 보관합니다. JSON은 임시 파일에서 교체하고 손상 자료를 자동 덮어쓰지 않습니다.
- [x] **S01-04 샘플 결과** — 기본 버튼은 실제 로컬 Gemma 생성 경로를 사용합니다. 고정 예시 시연은 별도의 접힌 영역으로 옮겼으며 내 파일을 고정 예시로 대신하지 않습니다. 생성 결과에는 읽은 기준 문제·변경 조건·AI 초안 표시를 넣었습니다.
- [x] **S01-05 오류와 처리 상태** — 처리 중 중복·입력 변경을 막고 단계·경과 시간·취소·서버 연결 오류·다른 모델·파일 오류·저장 실패를 안내합니다. 입력 수정 시 이전 결과를 해제합니다.
- [x] **S01-06 확인 기록** — 실제 WPF 화면, 자동 테스트, 설치판 확인 결과를 아래에 기록합니다.

## 간단 테스트와 완료 기록 · 2026-09-17

- 실행: 루트 `프로그램 실행.cmd`, 설치판 `artifacts/installer/EduMaster-MVP-Setup.exe`, 버전 0.3.0.
- 자동 테스트 44/44: 파일/저장·기존 공급자 계약·로컬 주소 제한·모델 확인·한글 입력·잘린 응답·원문 연결 검사.
- WPF 회귀 15/15: 키 없는 설정·생성 버튼·원문 표시·저장/복구·작은 창·PDF·미지원·다른 모델·진행/취소·시연·저장 실패. 모델 HTTP 응답은 대역입니다.
- 실제 Gemma/OCR 4/4: 테스트 TXT의 로컬 생성 2회, 샘플 이미지 OCR, 원본 5페이지 PDF OCR. 계산/정답 연결은 좁은 예시에서 수동 확인했습니다.
- 사용자 데이터와 테스트 데이터는 분리합니다. 기존 Gemini 키 파일은 보존하지만 새 앱에서 읽지 않습니다.
- 다음: 02의 독립 계산·화학 검증·교사 검토. SQLite·문제은행·학습지·학생·OMR은 후속 단계입니다.

### 외부 확인용 웹 MVP · 2026-09-17

- `/edumaster/`에 모바일 웹 화면을 추가하고 기존 서버의 사용자 서비스로 배포했습니다. 80/443의 기존 사이트·Planner·KidsNote는 정상 동작을 확인했습니다.
- 파일 입력·OCR 본문 수정·실제 Gemma 생성·단계/시간/취소·정답/해설·복사·인쇄/PDF를 제공합니다. 모바일에서 생성 시 결과 영역으로 이동합니다.
- 외부 TXT 업로드→실제 생성, 이미지 OCR, 업로드 삭제, 잘못된 형식 거부, 접속 제한, 실제 모델 기록 등 API 검사 8/8. 브라우저 생성 버튼에서 결과 표시와 모바일 가로 넘침 없음도 확인했습니다.
- 웹 UI는 서버에 있고 생성·OCR은 Windows PC에서 수행합니다. 그 PC가 절전 상태면 생성이 불가능하며 자동 기상·전원 설정 변경은 하지 않았습니다. Windows 앱의 사용자 workspace는 웹에 복사하지 않습니다.
